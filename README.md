# Career Nexus

**Live site: https://naman-singh-777.github.io/Career-Nexus/**

Backend API: https://career-nexus-api-hcfs.onrender.com (health check at `/api/health`)

Career Nexus takes one resume and returns an ATS read of the document, two or three career paths researched against live search results, and a week-by-week learning roadmap for the path you pick. The first request after a quiet period can take a few seconds, because the backend runs on Render's free tier and sleeps when idle.

## Before and now

Career Nexus began as a one-shot Python script. PyPDF2 extracted text from a PDF, spaCy parsed skills, and TF-IDF plus a small Sequential MLP matched them against a synthetic 100-row CSV of careers.

Version 2 is a web app. The React frontend is hosted on GitHub Pages and the Express backend on Render. Gemini does the reasoning the old pipeline did with separate libraries, and career data comes from Google Search results instead of a fixed CSV.

| | Before | Now |
|---|---|---|
| Form | One-shot Python script | React single-page app with an Express API |
| Resume input | PDF only, through PyPDF2 | PDF, DOCX, DOC, and TXT |
| Skill parsing | spaCy | Gemini with a strict JSON schema |
| Matching | TF-IDF and a Sequential MLP | Gemini reasoning over a researched brief |
| Career data | Synthetic 100-row CSV | Live Google Search grounding |
| Hosting | None | GitHub Pages (frontend) and Render (backend) |

## What you get

1. **Resume upload.** Drop in a PDF, DOCX, DOC, or TXT file up to 12MB. PDFs go to Gemini as native binary so the layout survives. DOCX and DOC files have their text extracted on the server first, since Gemini has no native reader for them.
2. **ATS score.** A 0 to 100 read of the document itself, with separate scores and notes for keyword clarity, section structure, quantified impact, and formatting risk. It measures how cleanly an applicant tracking system would parse the file, not how well it matches any one job posting.
3. **Persona question.** You pick Student, Fresher (0 to 1 years, first real role), or Working Professional.
4. **Direction question.** Working professionals choose between growing in their current lane and switching into something new. Students and freshers skip this step and go straight to transition paths, because they have no current lane to stay in.
5. **Career blueprints.** Two paths for someone staying in their lane, three for someone transitioning. Each blueprint has a fit score, a narrative about why it suits your background, a salary range, a growth outlook, a skill-gap radar (your level against the role's), industry-compatibility bars, and a short list of reasons it fits. Up to six source links from the search research appear under the cards.
6. **Learning roadmap.** Pick a blueprint and get four ordered stages: Foundations, Core Practice, Advanced, and Interview and Test Prep. Each stage has an estimated duration in weeks and two to four topics. Every topic links to a YouTube search for it.

If a request fails, the app returns you to the last screen that asks you something, with a short message, so you can retry without re-uploading.

### AI layer

| Piece | Detail |
|---|---|
| Reasoning model | `GEMINI_MODEL_REASONING`. The code default is `gemini-3.1-pro-preview`. The deployed backend sets `gemini-3.5-flash`. |
| Fast model | `GEMINI_MODEL_FAST`, default `gemini-3.5-flash-lite`. Used for the roadmap, which is a structuring task. |
| Structured output | Every call passes a `responseSchema` from `server/src/schemas.js`, so the profile, blueprint, and roadmap shapes are enforced by the API. |
| Thinking level | `HIGH` for resume parsing and career research, `MEDIUM` for the roadmap. |
| Search grounding | The research step enables `tools: [{ googleSearch: {} }]`, so salary ranges and requirements come from search results. |
| Retries | Transient failures are retried twice with exponential backoff and jitter. |
| Error messages | Raw API errors never reach the browser. Routes return one plain sentence instead. |

## How the AI pipeline works

```
resume file
   |
   v
POST /api/resume    ->  profile + ATS score          (reasoning model)
   |
   v
POST /api/careers   ->  1. grounded research brief   (reasoning model + Google Search)
                        2. blueprints as strict JSON (reasoning model + schema)
   |
   v
POST /api/roadmap   ->  staged learning plan         (fast model + schema)
                        YouTube search URLs built in code
```

**Resume.** `server/src/routes/resume.js` converts the upload into Gemini parts and asks for a profile that matches `PROFILE_SCHEMA`. The prompt tells the model to infer skills implied by project and work descriptions, to estimate proficiency conservatively from evidence, to leave out employers, dates, and credentials that are not in the document, and to infer career stage from graduation dates, internships, and years of experience.

**Careers.** `server/src/routes/careers.js` makes two calls. The first uses Google Search to write a plain-text research brief on current job requirements, salary ranges, and demand for the roles that fit the profile. The second turns that brief into the blueprint JSON. Fit scores and salary ranges are meant to come from the brief, not from the model's memory.

If the search call fails because the Google Search grounding quota is used up, the route repeats the research step once without the search tool and has the model answer from its own knowledge. The response then carries `grounded: false` and an empty `sources` list. Grounding has its own, smaller free-tier quota, separate from plain text generation, so this can happen even when the model itself still has quota.

**Roadmap.** `server/src/routes/roadmap.js` sends the profile and the chosen blueprint to the fast model and asks for four stages that close this candidate's listed skill gaps first. Gemini writes a natural search phrase for each topic. `server/src/youtube.js` encodes that phrase into a `youtube.com/results?search_query=...` URL. The model is never asked to name a specific video, because it cannot guarantee one exists.

**Retries and errors.** `server/src/gemini.js` is the only file that calls the SDK. Its `generateContent` wrapper retries HTTP 429, 500, 503, and 504 responses, and the API statuses `UNAVAILABLE`, `RESOURCE_EXHAUSTED`, `INTERNAL`, and `DEADLINE_EXCEEDED`. It waits about one second before the first retry and about two before the second. Anything else, such as a bad request or an auth failure, fails immediately. `friendlyErrorMessage` turns the SDK's raw JSON error body into a sentence like "Gemini is overloaded right now. Please wait a few seconds and try again." The full error is still logged on the server.

## API reference

| Method and path | Input | Response |
|---|---|---|
| `GET /api/health` | none | `{ "ok": true }` |
| `POST /api/resume` | Multipart form, field `resume` (PDF, DOCX, DOC, or TXT, up to 12MB) | `{ profile }` |
| `POST /api/careers` | JSON `{ profile, direction }`, where `direction` is `"transition"` or `"stay"` | `{ blueprints, sources, grounded }` |
| `POST /api/roadmap` | JSON `{ profile, blueprint }` | `{ careerTitle, overview, stages }`, each topic with a `youtubeUrl` |

Errors come back as `{ "error": "<plain sentence>" }`. A missing file, or a document that is unreadable or empty, returns a 400. An unsupported file type, a file over 12MB, and Gemini failures return a 500, and Gemini failures carry the friendly message.

`/api/careers` returns three blueprints when `direction` is `"transition"` or the profile's career stage is `student` or `fresher`, and two otherwise.

## Data shapes

All three shapes live in `server/src/schemas.js`, so what Gemini is constrained to return and what the frontend renders stay in one place.

- **Profile.** Name, current role, career stage (`student`, `fresher`, `early_career`, `mid_career`, `senior`), years of experience, a short summary, skills with a category and a 0 to 100 proficiency, experience entries, education entries, strengths, gaps, and the ATS score with its per-factor breakdown.
- **Blueprint.** Title, track (`transition` or `advancement`), compatibility score, narrative, reasons it fits, required skills with importance, skill gap entries (your level and the required level per skill), salary range with currency, growth outlook, and industry compatibility factors with scores.
- **Roadmap.** Career title, overview, and ordered stages. Each stage has a name, order, duration in weeks, description, and topics. Each topic has a name, a rationale, and a YouTube search phrase.

## Run it locally

You need Node.js and a free Gemini API key from https://aistudio.google.com/apikey.

```bash
cd server
cp .env.example .env
# paste your key into GEMINI_API_KEY=
cd ..

npm run install:all
npm run dev
```

This starts Express on `:8787` and Vite on `:5173`. Vite proxies `/api/*` to Express. Open http://localhost:5173.

To run it as one process, the way a single server would host it:

```bash
npm run build   # builds the React app into client/dist
npm start       # Express serves the API and the built frontend on :8787
```

Then open http://localhost:8787.

## Deployment

The live version is split across two hosts, and both redeploy when you push to `main`.

**Frontend on GitHub Pages.** `.github/workflows/deploy-pages.yml` installs the client with `npm ci`, builds it with Vite, and publishes `client/dist`. It runs when a push changes `client/` or the workflow file, and it can also be started by hand. `VITE_API_BASE_URL` comes from a repository Actions variable and points the built app at the Render backend.

**Backend on Render.** `render.yaml` defines a free Node web service with `server` as its root directory, `npm install` as the build command, and `npm start` as the start command. `GEMINI_API_KEY` is set in Render's dashboard and never committed. After a deploy, `GET /api/health` should return `{"ok":true}`.

GitHub Pages only serves static files and cannot run the Node server that holds the API key, which is why the two halves are hosted separately. See `DEPLOYMENT.md` for the setup notes.

## Swapping models

Free-tier limits change between Gemini releases. If you see 429 errors, change the model names in `server/.env` locally, or in the Render dashboard for the live backend:

```
GEMINI_MODEL_REASONING=gemini-3.5-flash
GEMINI_MODEL_FAST=gemini-3.1-flash-lite
```

Changing the model does not change the Google Search grounding quota. If grounding is the thing that is capped, the careers route falls back to ungrounded research as described above.

## Known limits

- Render's free tier sleeps after a period without traffic. The first request after that waits for the service to wake.
- Gemini's free tier caps requests per minute and per day. The backend retries short spikes, but a used-up daily quota shows a rate-limit message until it resets.
- Nothing is saved. There are no accounts and no database, so refreshing the page or starting a new scan clears the session.
- Resume contents are sent to the Gemini API for analysis. The server keeps the upload in memory only and does not write it to disk.

## Extending

- Persona and direction logic is in `client/src/state/useJourney.js`.
- Everything that talks to Gemini goes through `server/src/gemini.js`. If the `@google/genai` call shape changes, that is the file to update.
- To use real video results instead of search links, replace `buildYoutubeSearchUrl` in `server/src/youtube.js` with a call to the YouTube Data API. The roadmap route uses it in one place.
- New response fields go in `server/src/schemas.js` first, then the component that renders them.
